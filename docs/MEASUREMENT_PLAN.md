# 职语 Coach：数据指标与测试优化方案

## 1. 核心判断

这个产品的价值不是“AI 能回答问题”，而是用户能否更轻松地完成一次职场英语练习，并愿意再次练习。

第一阶段北极星指标：

**每周完成有效练习的人次**

有效练习定义：进入陪练后至少提交 2 次回答，并成功到达报告页。

## 2. 已加入的匿名事件

| 事件 | 触发时机 | 能回答的问题 |
| --- | --- | --- |
| `practice_started` | 点击开始陪练 | 有多少人愿意开始 |
| `answer_submitted` | 每次提交回答 | 用户是否真的参与练习 |
| `mixed_language_used` | 系统处理中文或中英混说 | 降低开口门槛是否有价值 |
| `recording_started` | 开始录音 | 语音功能使用情况 |
| `practice_completed` | 完成整轮练习 | 核心流程完成情况 |
| `report_viewed` | 打开报告页 | 报告是否成功送达 |
| `voice_enabled` | 打开 AI 考官语音 | 听力互动功能使用情况 |
| `api_fallback` | 真实接口失败并进入兜底 | 真实链路稳定性 |

当前埋点不记录：

- 用户回答原文。
- 录音内容。
- 姓名、手机号、微信号。
- OpenAI API Key。

## 3. 首轮验证指标

### 产品漏斗

- 开始练习次数：`practice_started`
- 回答提交率：至少一次 `answer_submitted / practice_started`
- 三轮完成率：`practice_completed / practice_started`
- 报告到达率：`report_viewed / practice_completed`
- 语音启用率：`voice_enabled / practice_started`
- 中英混说使用率：`mixed_language_used / practice_started`

V1 目前按事件次数统计。要计算准确的独立用户率和留存率，需要增加匿名用户 ID、练习 session ID 和持久化数据库。

### AI 质量

每个维度采用 1 至 5 分人工评分：

| 维度 | 5 分标准 |
| --- | --- |
| 原意保留 | 英文整理版完整保留用户信息，不编造经历 |
| 英文自然度 | 符合真实面试或会议口语，不像逐字翻译 |
| 反馈具体度 | 明确指出哪句话、什么问题、如何修改 |
| 追问相关性 | 追问紧扣上一轮回答和目标岗位 |
| 建议可执行性 | 用户下一轮可以立刻照着改 |
| 报告一致性 | 总结与实际对话一致，评分有依据 |

首轮目标不是追求完美分数，而是找出失败类型。每种失败至少保留一个评测样本，防止后续版本再次出现。

### 工程质量

- 自动测试通过率。
- 接口成功率。
- 平均响应时间。
- 最大响应时间。
- `429`、`500` 等错误占比。
- 录音上传失败率。
- 真实接口进入兜底的比例。

正式上线后应增加 P50、P95 延迟。目前本地指标只记录平均值和最大值。

## 4. 5 至 10 人可用性测试

每位测试者完成同一任务：

1. 选择“英文面试 + 产品经理 + 严厉考官”。
2. 打开 AI 考官语音。
3. 用中英混说完成第一题。
4. 用纯英文完成后两题。
5. 查看报告并选择一条表达重新说一遍。

测试前询问：

- 你对英文面试开口的信心是几分？`1-5`
- 你最担心什么？

测试后询问：

- 完成练习后的信心是几分？`1-5`
- 哪条反馈最有用？
- 哪一步最困惑？
- 明天是否愿意再练一次？
- 是否愿意为“7 天外企面试冲刺包”付费？可接受价格是多少？

第一轮建议目标：

- 至少 5 名目标用户。
- 至少 80% 能独立完成任务。
- 至少 60% 认为反馈具体有用。
- 至少 3 人愿意第二天再次练习。

这些是验证目标，不是当前已经取得的成绩。

## 5. 每次优化怎么做

1. 从错误日志、用户观察或评测集中发现问题。
2. 将问题变成可复现的测试样本。
3. 修改 Prompt、交互或接口。
4. 运行 `npm run check`。
5. 有额度时运行真实模型评测。
6. 对比旧版本和新版本结果。
7. 只有评测提升且没有回归时才发布。
